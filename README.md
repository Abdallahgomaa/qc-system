# CGES — نظام إدارة جودة الأعمال الهندسية

تطبيق ويب عربي (RTL) لإدارة جودة التنفيذ في المشاريع الهندسية: سجلات الخرسانة،
اختبارات التربة، المواد والاختبارات، معايرة المحطات، مع لوحة مؤشرات وتنبيهات ذكية،
ومرفقات (صور/مستندات) تُضغط وتُخزَّن سحابياً، وتقارير قابلة للطباعة، واستيراد/تصدير
Excel، وسجل تدقيق (Audit Log).

الواجهة مبنية بـ **Streamlit** والبيانات والأسرار على **Supabase**
(PostgreSQL + Auth + Storage).

---

## 1) الميزات الرئيسية

- **أقسام السجلات الأربعة** بنماذج موحّدة (إضافة/تعديل/بحث/تصدير) مع تحقّق من المدخلات قبل الكتابة.
- **ضغط الصور تلقائياً** قبل الرفع (WebP) مع **معاينة وتحذير تلقائي** إن انخفضت دقّة الأرقام.
- **رفع الصور من كاميرا الهاتف** مباشرة (خيار «📷 التقاط الصور بالكاميرا»).
- **لوحة مؤشرات** بمقاييس وتنبيهات ذكية (28 يوم أقل من الإجهاد التصميمي، نتائج ساقطة، شهادات قاربت الانتهاء…).
- **إشعارات**: مشاركة التنبيهات على واتساب بلا أي إعداد، وإرسال بالبريد اختياري عبر SMTP.
- **تقرير شهري** عربي (A4) قابل للحفظ كـ PDF عبر الطباعة.
- **استيراد من Excel** مع تحويل أنواع آمن وتحقق صفّاً بصف.
- **سجل تدقيق** لكل عمليات الإضافة/التعديل/الحذف (للمسؤول).
- **عرض متجاوب** على الهاتف: بطاقات بصفّين، حقول بعرض كامل، جداول تمرير داخلية، RTL.

---

## 2) المتطلبات

- Python **3.11+**.
- مشروع Supabase (مجاني يكفي).
- الحزم في `requirements.txt` (streamlit، supabase، pandas، openpyxl، Pillow، plotly). الحدود الدنيا مُختبَرة فعلياً على **Streamlit 1.66** و**Python 3.12**.

---

## 3) التشغيل محلياً

```bash
# 1) البيئة والحزم
python -m venv .venv
.venv\Scripts\activate          # ويندوز
pip install -r requirements.txt

# 2) الأسرار
copy .streamlit\secrets.toml.example .streamlit\secrets.toml
# ثم افتح الملف واملأ SUPABASE_URL و SUPABASE_KEY (المفتاح العام Publishable/anon)

# 3) التشغيل
streamlit run app.py
```

ثم افتح <http://localhost:8501> وسجّل الدخول بحساب أنشأته في Supabase.

### تهيئة قاعدة البيانات (مرة واحدة)

نفّذ الملفات التالية بالترتيب في **Supabase ▸ SQL Editor**:

1. `schema.sql` — الجداول + سياسات RLS + Bucket المرفقات `cges-files` + جدول التدقيق.
2. `migrations/001_audit_log.sql` — تأكيد جدول `audit_log` وسياساته (البند 3.7).

### حسابات المستخدمين

- تُنشأ الحسابات في **Supabase ▸ Authentication ▸ Users** (البريد وكلمة المرور).
- يُسجَّل الدخول في التطبيق بـ**اسم المستخدم** (يُكوَّن البريد داخلياً على نمط
  `username@cges.com`).
- من تمنح **صلاحية المسؤول**: أي مستخدم يحتوي اسمه/بريده على `admin`
  (مثال: `admin@cges.com`).
- إدارة المشاريع والمستخدمين من شاشة **الإدارة** داخل التطبيق.

## 4) النشر على Streamlit Community Cloud (البند 2.6)

1. **ارفع المشروع إلى GitHub** (مستودع عام أو خاص).
   - تأكّد أن `.streamlit/secrets.toml` **غير مرفوع** (‏`.gitignore` يتكفّل بذلك، وتم
     إخراجه من فهرس Git فعلياً؛ إن سبق رفعه فأبطِل مفاتيحه وأنشئ غيرها).
   - الملفات التي يجب أن تبقى مرفوعة: `.streamlit/config.toml`،
     `.streamlit/secrets.toml.example`، `schema.sql`، `migrations/`، `tests/`،
     `.github/workflows/keepalive.yml`.
2. افتح <https://share.streamlit.io> ▸ **New app**.
3. اختر المستودع والفرع (`main`) وملف التشغيل **`app.py`**.
4. من **Advanced settings ▸ Secrets** الصق محتوى ملف الأسرار:

```toml
SUPABASE_URL = "https://YOUR-PROJECT-ref.supabase.co"
SUPABASE_KEY = "sb_publishable_XXXXXXXXXXXXXXXXXXXXXXXX"
```

5. اضغط **Deploy**. الفحص الصحي للتطبيق يكون على:
   `https://<app-name>.streamlit.app/_stcore/health` (يُرجع `ok`).
6. إن ظهرت مشكلة إصدار Python، أضف ملف `runtime.txt` يحتوي سطراً واحداً مثل
   `python-3.12` ثم أعِد النشر.

> **ملاحظة أمنية:** لا تضع أبداً مفتاح الخدمة `service_role` في أسرار التطبيق.
> المفتاح العام + تسجيل دخول المستخدم كافيان، لأن صلاحيات الجداول والتخزين
> محميّة بسياسات RLS في `schema.sql`.

## 5) منع الخمول (Keep-alive) — البند 3.6

مشروع Supabase المجاني يُوقف بعد ~7 أيام بلا نشاط، والتطبيق المنشور قد «ينام».
سير العمل `.github/workflows/keepalive.yml` ينفّذ طلباً يومياً (‏06:17 UTC) لمنع ذلك.

أضف في GitHub: **Settings ▸ Secrets and variables ▸ Actions ▸ New repository secret**:

| السرّ | إلزامي | القيمة |
|---|---|---|
| `SUPABASE_URL` | نعم | عنوان مشروع Supabase |
| `SUPABASE_KEY` | نعم | المفتاح العام (Publishable/anon) |
| `APP_URL` | لا | عنوان التطبيق المنشور، مثال `https://xxxx.streamlit.app` |

يمكن تشغيله يدوياً من تبويب **Actions ▸ Keep-alive ▸ Run workflow**.

## 6) إشعارات البريد (اختياري) — البند 4.2

أضف قسم `[smtp]` إلى الأسرار (محلياً أو في Streamlit Cloud) لتفعيل زر
«إرسال التنبيهات بالبريد» في لوحة المؤشرات:

```toml
[smtp]
host = "smtp.gmail.com"
port = 465
user = "your-address@gmail.com"
password = "app-password"
sender = "your-address@gmail.com"
recipients = "engineer1@example.com, manager@example.com"
```

دون هذا القسم يعمل التطبيق طبيعياً، وتبقى مشاركة التنبيهات على واتساب متاحة.

## 9) ملاحظات تشغيلية

- **بعد أي تعديل على ملفات المشروع:** أوقف الخادم وأعِد تشغيله، لأن Streamlit
  يحتفظ بالوحدات في الذاكرة.
- **الكاش:** طبقة القراءة تُخزَّن مؤقتاً (~60 ثانية)؛ عند تعديل البيانات خارج
  التطبيق انتظر انتهاء المدة أو أعِد تشغيل الخادم لرؤية التحديث.
- **مسح تنبيه جرس التنبيهات:** أي صبّة يكون فيها `result_28d_mpa` أقل من
  `design_strength_mpa` تُظهر تنبيهاً حرجاً في لوحة المؤشرات.
- **إصدار Streamlit:** التطبيق مُختبَر على **1.66**؛ معاينة التقرير تستعمل `st.iframe`
  (البديل الحديث لـ `st.components.v1.html` المهجورة) مع احتياط تلقائي للإصدارات الأقدم.
